# MyKeyboardTyping - システム全体設計ドキュメント

## 1. プロジェクト概要

### 1.1 目的
自作キーボード（特にカラムスタッガード分割キーボード）のユーザーが、キーボード固有のキー配列に合わせてタイピング練習を行うためのWebベースツール。

### 1.2 対応キーボード
- **現在対応**: 
  - Corne (crkbd)
  - Cornelius v2
  - Ergo68
  - ErgoArrows
  - Helix rev3 5rows
  - Keyball39
  - Keyball44
  - Lily58
- **キーマップ取得方法**: 静的JSONファイル（`public/keyboards/*.json`）
- **非VIA対応キーボード**: キー配列表示なしでタイピング練習が可能

### 1.3 主要機能
1. **キーボード可視化**
    - JSONファイルによるキーボードレイアウトの動的描画
    - 入力されたキーのハイライト表示
    - 全レイヤー同時表示および個別表示切り替え機能

2. **タイピング練習機能**
    - ビルトイン練習素材の提供
      - 日本語: 単語、文章、数字など（ハイフン、外来音対応）
      - 英語: 基本単語、技術用語、プログラミング用語、数字
      - 数学: 数式、演算子など
      - C#: プログラミング用語
    - リアルタイムキー入力検出と表示
    - 入力状況の可視化（入力済み部分の色分け）

3. **統計情報の表示**
    - 正確率（%）
    - 正答数・誤答数
    - WPM（Words Per Minute）※将来実装検討

4. **誤入力ハンドリング**
    - 誤入力時のビジュアルフィードバック
    - 正しい入力まで進行しない（スキップ不可）

## 2.5. WebHID API統合

### キーボード検出処理

WebHID APIを使用してVIA/Remap対応キーボードを検出します。

**検出フロー**:
```
1. WebHID API の `navigator.hid.requestDevice()` を呼び出し
2. ユーザーがOS側のダイアログでキーボードを選択
3. デバイスのVID/PIDを確認
4. 対応キーボード一覧と照合
5. JSONファイルが存在すればキーマップを読み込み
6. 検出されたキーボード情報を画面に表示
```

**VID/PID管理**:
- 各キーボードのJSONファイルにvendorId、productIdを含める
- 将来的に他キーボード対応時は、JSONファイル追加で対応

**エラーケース**:

| シナリオ | 対応 |
|--------|---------|
| WebHID未対応ブラウザ | ブラウザ非対応メッセージ + リンク提示 |
| ユーザーがダイアログをキャンセル | 選択画面に戸る（エラー表示なし） |
| VIA非対応キーボード接続時 | 警告メッセージ表示 + キー配列なしで練習可能 |
| JSONファイルがない場合 | キー配列表示なしで練習可能 |

## 3. ユースケースフロー

### 3.1 初期化フロー
```
1. ユーザーがアプリケーションにアクセス
2. イントロダクションセクションと対応キーボード一覧を表示
3. ユーザーが「キーボードを選択」ボタンをクリック
4. WebHID API経由でキーボード選択ダイアログを表示
5. ユーザーがキーボードを選択
6. 選択されたキーボードが対応リストにあればキーマップを取得・表示
7. 非対応キーボードの場合、キー配列表示なしで練習画面を初期化
8. タイピング練習開始
```

### 3.2 タイピング練習フロー
```
1. 練習素材選択画面が表示される
2. ユーザーが練習素材を選択
3. 練習画面に遷移し、選択した素材のテキストが表示される
4. ユーザーがキーボードでテキストを入力
5. 各キー入力時：
    a. キーボード画像上で該当キーをハイライト
    b. 入力テキスト上で入力位置を示す
    c. 正誤判定を実行
6. 正入力時：
    a. キーをハイライト（成功表示）
    b. 入力位置を進める
7. 誤入力時：
    a. エラーエフェクト表示（入力テキスト）
    b. 入力位置は進まない（再入力待ち）
8. 1単語の入力完了時：
    a. 次の単語に自動的に進む（複数単語の場合）
9. 全単語の入力完了時：
    a. 完了画面を表示
    b. 正確率、正答数、誤答数を表示
    c. 再挑戦または次の練習を選択可能
```

### 3.3 レイヤー表示管理フロー
```
1. 初期状態ではレイヤー0のみ表示
2. ユーザーは任意のレイヤーの表示/非表示を切り替え可能
3. 複数レイヤーの同時表示が可能
4. 各レイヤーで入力されたキーは全レイヤーで同時にハイライト
5. レイヤー切り替えキー（MO(n)）の自動検知は将来機能として検討
```

**注**: MO(n)キーによる自動レイヤー切り替えは、物理キー入力からの検知が困難なため、現バージョンでは実装していません。

## 7. エラーハンドリング戦略

### 7.1 キーボード関連
| エラーケース | 対応 |
|-------------|------|
| キーボード未検出 | リスト空表示 + メッセージ表示 |
| キーボード接続解除 | エラーメッセージ表示 + リトライオプション |
| キーマップ取得失敗 | エラーメッセージ + リトライボタン |

### 7.2 入力関連
| エラーケース | 対応 |
|-------------|------|
| 誤入力 | ビジュアルエラーフィードバック（赤色ハイライト等）|
| 予期しないキー | エラーエフェクト表示 + ビープ音（オプション） |
